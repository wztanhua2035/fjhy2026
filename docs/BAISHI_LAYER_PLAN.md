# 白石街正式分层地图接入规范

本文档只约束白石街正式美术接入，不改变服务端世界配置、碰撞规则或玩家数据结构。正式素材到位后，按本文档逐项替换当前完整插画背景和程序绘制占位物。

## 目标

白石街采用可交互的分层地图，不再使用“完整场景插画作为背景，再叠加人物和店铺”的正式方案。地图视觉与逻辑对象必须使用同一套场景坐标：地面、道路、建筑、装饰、玩家/NPC、前景遮挡、碰撞和入口分别管理。

## 图层顺序

从后到前固定为：

1. `ground`：草地、石板、道路、水渠底色和岸边基础。
2. `buildings`：五家店铺独立建筑主体。建筑由 Plot 配置挂载，不写死在背景图中。
3. `decorations_back`：树干、灌木后部、花坛、路灯、长椅、小摊、木箱和货物。
4. `actors`：玩家、剧情 NPC、生活 NPC 和 Ghost。所有人物使用脚底锚点排序。
5. `foreground`：树冠下沿、屋檐前沿、门廊顶棚和前景枝叶，只覆盖需要遮挡的人物部分。
6. `interaction`：入口、交互提示、任务标记等 UI/调试可视层，不属于地图美术本体。
7. `collision`：不可见的服务端和客户端碰撞区域，与美术层分离。

`collision` 和 `interaction` 不应被烘焙进美术 PNG；它们继续由场景配置和运行时逻辑提供。

## 当前场景坐标基准

当前白石街为 `STREET_BAISHI_01`，80×80 格，单格 32 像素，逻辑范围为 2560×2560 像素。主道路位于 `y=38..44`，纵向道路位于 `x=38..43`。正式美术接入必须以这套逻辑坐标校准，而不是以展示板或完整插画中的像素位置猜测。

这些坐标是交互和碰撞的权威数据。独立建筑 PNG 的门口、建筑底线和占地范围必须在接入时与对应 Plot 对齐；若美术比例不适合当前 Plot，应调整美术缩放和锚点，不能擅自移动入口逻辑。

## 对象锚点与遮挡

- 建筑锚点使用建筑底部中心或配置的入口基线；建筑阴影随建筑资源提供或由统一规则生成。
- 玩家和 NPC 的世界坐标代表脚底中心，不代表身体中心。角色绘制应将脚底放在该坐标，阴影贴地并位于脚底正下方。
- Actors 按脚底 `y` 排序；相同或接近的 `y` 使用稳定次序，避免帧间闪烁。
- 树冠和屋檐前沿必须进入 `foreground`，不能只作为完整树木或完整建筑的一部分放在 actors 下方。
- 前景遮挡只覆盖图像实际需要的区域，不能遮住交互提示和 UI。
- 玩家、NPC、建筑和装饰使用同一套色彩、描边、阴影和透视约定；不再使用与正式背景独立的程序色块建筑。

## 接入顺序

1. 接入地面/道路层，确认主路宽度、纵横道路和镜头裁切。
2. 按五个 Plot 依次挂载独立店铺，先校准客栈、杂货铺和商行。
3. 加入后景装饰，确认道路仍然清晰可走。
4. 将玩家、NPC 和 Ghost 的脚底统一到地图基线，校准人物相对于门和道路的大小。
5. 加入树冠、屋檐和枝叶前景层，验收前后遮挡。
6. 将碰撞和入口逐个与可见门口核对，再删除完整插画背景的正式使用路径。

## 手机预览验收

先在浏览器窄窗口检查布局，再用 Cocos Creator 预览，最后使用微信开发者工具或真机体验版检查：

- 竖屏/横屏适配和安全区域。
- 角色脚底不漂浮、不陷入道路或建筑。
- 角色与门、道路宽度和店铺高度比例自然。
- 走到树冠或屋檐下时出现正确遮挡，离开后恢复。
- 入口提示与实际门口重合。
- 背景、建筑、人物和阴影没有明显色温或描边断层。
- 场景切换、碰撞、NPC 对话和商店交互不受美术层影响。

## 当前资源边界

`baishi_street_scene_day_v01.png` 是完整场景插画，保留在 `art-source` 作为参考，不作为正式分层地图底图。正式接入只使用用户定稿后的独立地面、建筑、装饰和前景 PNG。缺少素材时使用简单占位几何图形，等待用户从普通聊天模式提供正式素材；不要在 Work 中批量生成替代素材。

## 完成定义

白石街只有在以下条件全部满足后，才可称为正式分层地图：

- 完整插画背景不再参与正式渲染。
- 五家店铺是独立资源并与 Plot/入口坐标对齐。
- 玩家和 NPC 使用统一脚底锚点和场景比例。
- 至少有一个树冠或屋檐前景遮挡实例通过验收。
- 碰撞区域和交互点仍由配置控制，并与可见对象一致。
- 浏览器、Cocos 预览和微信开发者工具的场景表现均通过检查。
