# 《富甲横阳》白石街模板规范 V1

白石街是后续街区的首个可复用样板。场景、任务和交易仍由共享配置与服务端状态决定；本规范只约束内容呈现、反馈节奏和资源边界。

## UI 模板

- **HUD**：场景标牌固定在右上安全区，使用 `sceneLabel` 简称；任务卡位于其下，可折叠，只显示任务标题和当前目标。互动按钮固定右下，文案只来自 Interaction Targeting。
- **对白**：下方居中 RPG 对话框，姓名牌区分主角、NPC、旁白；每页最多三行，半身像位于两侧并避开正文。对白进行时，普通通知排队等待。
- **任务**：接取、推进、完成分别使用简短通知；任务详情使用“标题 + 当前目标 + 完成态”，不在 HUD 叠加多段奖励信息。
- **背包**：分类筛选、物品格、选中详情、数量与可用状态同一面板；业务规则继续由 Inventory 层处理。
- **档案**：头像、姓名、外号、性格、铜钱与可读的外观摘要；不显示内部资源 ID 或调试字段。
- **商店与服务**：使用统一标题栏、铜钱区、条目卡、数量控制、结果反馈；商行可增加买入/卖出页签，Hair、Outfit 只替换服务内容。
- **通知与确认**：普通说明用 Toast，获得物品、任务、交易和休息用 Result；请求期间禁用重复点击，二次确认使用同一暖米白面板。

## 对白与任务反馈

- 核心 NPC 初次相遇先给一至两句与身份、地点有关的寒暄，再进入功能或委托。
- 委托的接取、关键交接、完成各保留一至两句短对白；文案描述人物行为，不重复系统提示。
- 主角对白采用自然、简洁的现代年轻人口吻；陈掌柜稳重平实，其他店员与店主用对应行业语气。
- 文案写在 Quest/NPC/Opening 配置中，Web 与微信只渲染共享状态。

## 场景与资源

- `sceneId`、`formalName`、`sceneLabel` 分离；背景图不承担正式地点名称，环境匾额可作为美术细节保留。
- 场景图、碰撞、portal、NPC 站位、interaction zone 和 service point 分层维护；仅修改美术时不得逆向改变坐标配置。
- 人物贴片使用 Phaser 的 `pixelArt`、关闭抗锯齿和整像素定位；保持 4×4、64px 帧、脚底锚点与既有组合逻辑。
- 大型正式资源走 Remote Asset、COS/CDN 和版本化 manifest；运行图经过体积预算校验，旧版本保留用于回滚。

## 双端验收清单

1. Web 先核对横屏安全区、中文换行、分页、空状态、禁用态与场景切换。
2. 微信随每批 UI 改动生成 clean build，核对胶囊避让、字体可读性、触控面积、资源加载和 Canvas 层级。
3. 回归开场、三条主任务、五家店、背包、档案、Hair、生活功能和场景标牌。
4. 自动测试验证配置和状态；Web 与微信真机/预览共同做最终视觉验收。
