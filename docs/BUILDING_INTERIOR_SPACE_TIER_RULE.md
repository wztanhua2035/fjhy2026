# 《富甲横阳》建筑内部空间三级规则 V1

本规则用于后续建筑、店铺、场景、NPC 与交互设计。建筑内部空间不追求数量和面积，而追求有用、有趣、有区别：大型场所提供探索，小型店铺提供紧凑互动，快速消费场所使用对话与菜单，兼顾小镇丰富度、开发效率与游玩节奏。

## 总原则

《富甲横阳》不要求所有建筑制作成可自由行走的大型室内场景。室内规模与实现方式由玩法密度、剧情重要度、NPC 数量、交互复杂度和探索价值决定，不由建筑外观面积决定。

> 需要探索的地方做空间，需要办事的地方做界面。

不要机械采用“进门 → 加载室内 → 走到 NPC → 对话 → 买东西 → 出门”的流程。快速消费和窗口服务应减少无意义移动与场景切换。

## A 类：完整室内空间

适用于客栈、酒吧、KTV、商场、医院、学校、政府大楼、大型餐馆及重要剧情据点等承担探索、社交、多 NPC 互动或大型事件的地点。

- 使用独立室内 Scene，玩家可自由移动。
- 可以有多个房间或区域、多个 NPC、任务点、调查点、小游戏、座位与柜台。
- 适合承载主线、支线、社交和大型事件。
- 制作成本最高，只在玩法需要时使用。

## B 类：紧凑型室内空间

适用于春衫衣坊、青丝美发室、小茶馆、小咖啡馆、药店、工作室、小型餐馆及有重要 NPC 的小店。

- 使用独立室内 Scene，但可只包含一个核心房间。
- 通常配置 1～2 名主要 NPC、一个柜台或工作区，以及少量装饰和互动点。
- 门口、NPC 与柜台之间保留基本移动空间即可；不必按现实建筑面积扩张。
- 可按 RPG 视觉比例压缩为十几至几十平方米小店的体验。

## C 类：无自由行走室内／对话菜单型店铺

适用于奶茶店、小卖部、小吃窗口、报刊亭、快递点、彩票店、手机维修点、小型便利窗口和路边摊等内部没有探索价值的场所。

- 原则上不创建独立可行走室内 Scene。
- 玩家在街道靠近建筑、柜台或窗口后，直接触发“互动 → 店主/店员对话 → 菜单或服务界面”。
- 完成购买或服务后关闭界面，玩家仍停留在街道原位置。
- 可使用轻度背景压暗、NPC portrait、简短对白和商品／服务菜单表达店内体验。

## 建筑规模与开放范围

建筑外观看起来有两层或面积很大，不代表当前版本必须全部开放。可以只开放一楼、柜台区域或一个房间；其余楼层在世界观中存在，但暂时不可进入。后续可通过支线、经营升级或剧情逐步开放二楼和新区域。

A、B、C 类可随玩法演进升级。例如 C 类奶茶店可先以店员对话和菜单提供服务，出现重要剧情后升级为 B 类小型室内，再发展为社交地点。建筑与场景数据不得永久锁死某种室内实现方式。

## NPC 与数据设计

A、B 类中可进入且承担剧情、交易或服务功能的店铺，继续遵循店铺核心 NPC 规则：至少配置一名具有稳定实体 ID 的核心 NPC。

C 类也可以拥有正式核心 NPC。即使没有室内 Scene，该 NPC 仍可通过 portrait、对话、商品／服务菜单、支线任务与好感关系参与游戏，不能因其表现为 UI 而失去独立身份。

后续数据层应预留可表达建筑互动方式的概念，例如 `interactionMode`：

- `INTERIOR`：完整室内空间；
- `COMPACT_INTERIOR`：紧凑型室内空间；
- `DIALOGUE_MENU`：街道对话与菜单。

本规则不要求立即新增字段或重构现有配置。新增字段时应采用新增字段加默认值的兼容方式，允许 C 类未来升级为 B 类或 A 类。

## 性能与资源原则

三级空间规则避免未来数十至上百个地点全部拥有大型独立地图。C 类及部分 B 类应避免不必要的 TileMap、大型背景资源、额外碰撞、场景切换与 NPC 寻路，从而降低微信小游戏包体和手机内存压力，并减少美术、场景维护与玩家操作成本。

## 当前白石街参考

- 横阳客栈：A 类。
- 青丝美发室：B 类。
- 春衫衣坊：B 类。
- 街坊杂货铺：B 类，后续可按玩法需要简化。
- 后续奶茶店、小卖部等优先评估 C 类。

本规则不要求对当前已完成场景返工；从新增建筑和自然迭代开始执行。

## 新建筑判断清单

新增一家店前，先回答：

1. 玩家为什么需要进入里面？
2. 里面是否有值得走动探索的内容？
3. 是否有多个 NPC 或多个互动点？
4. 室内是否承担剧情或社交功能？
5. 如果只是购买或接受服务，是否可由对话和菜单完成？

如果进入并走动没有增加明显乐趣，优先采用更轻量的实现。
