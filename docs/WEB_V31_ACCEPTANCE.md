# Web 收口 V3.1 验收记录

日期：2026-09-15。范围仅为 Web 生活面板、创建排版、场景切换和反馈展示；没有修改图片、manifest、碰撞、任务或经济规则。

## 根因与修复

- 背包的旧 `#inventory` 容器仍带白色面板样式，新窗口又嵌在其中。窗口改为 HUD 直属节点，旧节点只保留入口；Inventory、Profile、Shop 采用共享 `rpg-modal` 外壳，生活设施由 `createRpgModal` 生成同一套标题、关闭、遮罩、正文和 footer。
- Storage 双列共用物品卡，点击左/右列明确选择存入/取出；数量和结果位于 footer。床采用三种休息卡与确认按钮；衣柜采用完整图层预览、四方向按钮和衣服卡；书桌提供任务摘要与档案入口。
- Web 停用旧 Canvas 生活设施及 Outfit 面板，避免双通道显示；微信维持原界面。服务入口共用固定宽度的 Context Action 样式和处理中状态。
- 旧位置确认提示混入普通通知，场景加载及 ghosts 响应缺少序号保护，通知没有场景归属。现在每次加载拥有 transitionId 和加载序号，迟到响应不能覆盖新场景；场景提示同时验证 sceneId/transitionId。
- Loading 等待超过 300ms 才显示“正在进入…”，scene 数据就绪立即关闭，不等待 Quest 请求或通知队列。普通重复到达提示不再入队，场景标牌直接更新。
- 即时操作反馈优先显示；任务/奖励顺序排队；环境提示绑定当前场景与切换序号，过期丢弃。Quest Tracker 直接读取最新 state。空操作消息会重置展示去重，允许下一次相同操作结果再次反馈。
- 第六步九句话正文统一 17px，小屏不再被旧 13px 规则覆盖，行高 1.55–1.6。

## 实际浏览器操作

使用隔离的内存测试 API 与 Web 页面，未清理用户存档：

- 临时房依次检查床、衣柜、箱子、书桌：休息选择/开始/结束；衣柜转向；大米存入两份及取回一份；书桌打开档案。
- 室内及白石街各打开背包，确认单窗口，无外层旧白框；档案也是单窗口。
- 创建流程走至第六和第七步。1366×768、1600×900、1920×1080 均实际截屏检查：九卡可读，正文 17px，卡片无内容溢出，页面无整体滚动。
- 同一角色实际走完临时房 → 客栈 → 白石街 → 春衫衣坊 → 白石街 → 青丝美发室。检查场景名称、门口、服务入口、打开服务面板；没有迟到的“已到达白石街”或残留位置确认。
- 新衣服面板购买青绿短衫裙：120 文变为 10 文，重登仍为当前穿着；尝试购买 150 文衣服，底部立即显示余额不足，商品清单不受遮挡。
