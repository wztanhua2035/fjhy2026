# 《富甲横阳》Global UI Design System V1

本规范只描述呈现与触控。任务、交易、存档、外观和世界坐标仍由原有共享业务层决定。Web 使用 DOM/CSS，微信使用 Phaser Canvas；两端共用 `packages/client-runtime/ui-design-tokens.ts` 的语义色、字号层级和交互状态。

## 视觉基础

- 气质：清新、温暖、轻日式 RPG，小镇生活感；背景为浅灰绿，面板为暖米白，主强调为低饱和青绿。
- 颜色：`bgPrimary/bgSecondary` 为底层，`panel/panelElevated` 为容器，`textPrimary/textSecondary/textMuted` 为信息层级；`accent/accentSoft` 为普通操作，`success/warning/danger` 为反馈，`divider/mask` 为边界和遮罩。
- 字体：`titleXL/L/M` 为 28/24/20，`bodyL/M/S` 为 20/17/15，`caption` 为 13，数字与价格为 19；对白正文与姓名牌另用 27/23 的手机画布尺寸。中文优先系统黑体，不引入大型字库。
- 间距：4/8/12/16/24；圆角：8/12/18；边框常规 2。按钮反馈使用 120ms，普通过渡 200ms，较慢过渡 300ms。禁用透明度 0.48。
- 层级：世界 < HUD < 功能面板 < 半身像 < 对话 < 确认窗口 < 通知。所有 Canvas 控件置于独立 UI Camera；不改变世界 Camera。

## 组件与触控

- Primary/Secondary/Ghost/Danger/Icon/Disabled 共享同一字号、圆角和最小触控面积。主按钮建议不低于 52 画布单位，其他可点击对象不低于 44。网络处理中禁用重复提交，服务端幂等规则保持不变。
- Modal、SidePanel、BottomPanel、Card、Tooltip、Toast、ResultCard、ConfirmDialog 使用同一暖米白面板、浅色边界和轻阴影；空列表显示自然文案。复杂面板适合左右信息区，不把世界视野完全遮住。
- 横屏安全区：系统 safe area 左右至少再留 18；微信胶囊下沿另留 12。任务、关闭、铜钱、互动和菜单不贴边。不同宽高比以可用区域布置，不改变玩家坐标。

## 主 HUD、任务与交互

主 HUD 显示场景和铜钱；活力放在档案及休息面板，避免常驻大条。任务卡只显示任务名和当前目标，可折叠。互动按钮固定在右下，宽度稳定，标签由现有 Interaction Targeting 提供，UI 不扩大可交互范围。

## 对话

- 下方 JRPG 对话框居中，宽约屏幕 78–79%，高不超过 142–152 画布/CSS 像素；每页至多三行。长文本由 `paginateDialogue` 分页，轻点继续。
- 半身像位于对话框后方两侧。较窄的对话框为头、肩和更多上半身留出空间；文字始终在框内，不覆盖面部。
- 姓名牌位于框上沿。主角使用青蓝 `speakerPlayer`，NPC 统一暖杏 `speakerNpc`，旁白用中性灰 `speakerNarrator`。主角牌显示正式姓名。正文统一暖白 `dialogueBody`。
- 关键词只允许语义色 `dialogueKeyword/dialogueMoney/dialoguePlace`；业务文案不自行随机染色。

## 功能窗口

- 杂货铺与商行：同一商店容器，商品列表、详情、数量、价格与买卖动作同层级；商行使用买入/卖出 Tab。空出售列表明确显示说明。
- Hair/Outfit：共享面板色、按钮尺寸和预览位置；预览、当前状态、费用与确认分开。衣柜仅显示已拥有服装，购买仍去衣坊。
- 背包/Storage：物品列表和所选详情分开，空状态明确；存取方向清楚。休息只给时间、简短说明与轻量活力信息，不显示内部公式。
- 个人档案：正式姓名、外号、四字性格与轻量状态；正常界面不展示内部资源 ID。
- 创建角色：七步向导，人物预览、选择内容、上一步/下一步位置固定。姓名页给出长度提示和随机按钮；九句性格话语为可滚动的大卡片，玩家不见内部标签；最后确认显示原句。

## 通知与测试

Toast 用于简短错误或说明；ResultCard 用于交易、休息、任务等结果。`UiNotificationQueue` 依次显示，通常 2.1 秒或 2.8 秒，不叠三个结果窗口。正式业务响应仍由服务端决定。

每次新增 UI 应核对：手机横屏安全区、触控面积、禁用态、长中文换行、内容为空、请求中状态、Web/微信一致、对白分页和半身像遮挡。微信真机视觉和低端机 FPS/内存是最终验收；自动测试不能代替真机。

本地 Vite 开发服务器可打开 `/ui-playground.html` 查看按钮、卡片、结果和三类说话人姓名牌；该页面不调用游戏业务 API，正式构建只以游戏入口为交付物。
